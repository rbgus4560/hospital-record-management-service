# 설계·처리 원칙

선택 당시 개인 의도는 확인되지 않아 현재 코드의 동작과 근거를 기술한다.

- OCR Secret은 backend/.env에서 읽고 React에서 외부 OCR을 직접 호출하지 않는다.
- 입력 형식·Base64·파일 시그니처·10MB 크기와 외부 API 오류를 확인한다.
- OCR 좌표·제목·행 그룹을 사용해 특정 서식 영역을 해석한다. 범용 문서 이해 모델로 표현하지 않는다.
- 원본 필드 인덱스·신뢰도·미할당 후보·경고를 남겨 검수 경로를 유지한다.
- 사용자가 확인한 일정을 반영하고 후보를 확정 정보로 자동 취급하지 않는다.
- OCR 재파싱과 재호출을 구분한다. 실제 호출 비용 절감 수치를 측정한 것은 아니다.
- PDF/ZIP은 브라우저에서 생성하며 보험사 제출과 구분한다.
- 저장 기능은 현재 React 메모리이고 DB는 미구현이다. 과거 계획이 현재 구현처럼 보이지 않도록 README·프로필을 정정한다.

## 2026-10-25 · PostgreSQL 영구 저장

사용자가 새로고침 중 기록 소실을 보고하고 DB 연결을 요청했다. patients/documents/appointments 3개 테이블을 사용하고 OCR 원본은 JSONB, 원본 이미지는 BYTEA로 보존한다. 외래 키·문서 버전·트랜잭션으로 관계와 편집 충돌을 보호한다. 기존 React 메모리 저장 설명은 이전 상태이며 현재 구현·설정·제한은 [DB 설계](postgresql-schema-and-api.md)를 기준으로 한다. 실제 연결 검증 전에는 영구 저장 완료라고 보고하지 않는다.

## PaddleOCR 한국어 모델 실험

PP-OCRv5 모바일 검출기와 한국어 인식 모델을 CPU에서 실행한다. 인식 결과를 기존 필드 형식으로 변환해 원본 뷰어와 좌표 기반 파서를 재사용한다. 문서 회전과 평탄화는 원본 좌표를 유지하기 위해 끈다.

- 연동 코드 [paddle_ocr.py](../../backend/ocr/paddle_ocr.py)
- 비교 지표 [OCR 평가 절차](../../ocr-evaluation/README.md)

## Docker Compose 로컬 시연

React 빌드와 API를 Nginx의 동일한 주소로 제공한다. 브라우저가 상대 경로로 API를 호출하므로 호스트의 접속 IP와 포트를 바꿀 때 프런트엔드 이미지를 다시 빌드할 필요가 없다. PostgreSQL과 API는 Compose 네트워크에서 서비스 이름으로 연결한다.

PostgreSQL이 준비된 뒤 백엔드에서 기존 초기화 스크립트를 실행해 Windows 실행과 같은 스키마를 사용한다. 기록과 OCR 모델은 별도 볼륨을 사용해 컨테이너를 교체해도 보존한다.
