# 관찰 문제·제한 기록

정리일 2026-10-22. 제공된 과거 오류 로그·수정 이력이 없어 구현된 방어 처리를 실제 발생한 장애처럼 꾸미지 않는다.

## H-01 · 문서와 실제 기술 구조 불일치
- 상태: 문서 정정. 기존 원격 README는 Java/Spring Boot·PostgreSQL·LLM 요약 계획을 설명.
- 근거: 제공 코드의 FastAPI 엔드포인트·React useState 및 임시 저장 안내. DB/LLM 호출 코드 없음.
- 원인 가설: 계획과 현재 과제가 달라졌을 가능성. 정확한 변경 경위 미확인.
- 조치/검증: README·구성도·프로필을 현재 구현 기준으로 작성하고 구 코드·의료 자료 업로드는 하지 않음. 정적 코드 대조.
- 교훈: 기술 선정 계획과 현재 동작·저장 범위를 분리해서 설명한다.

## H-02 · Vite 번들 크기 경고
- 환경/증상: Node 24.19.0, Vite 8.3.4의 npm run build 성공. 메인 JS 약 746.61kB로 500kB 초과 경고.
- 상태: 미수정 경고. 빌드 실패로 표현하지 않음.
- 시도: 정상 빌드만 수행. PDF 관련 모듈 포함이 원인 후보이나 모듈별 기여도 프로파일링은 미수행.
- 검증: 빌드 exit 0, 224 modules transformed. 초기 로딩 체감·실측은 미측정.
- 후속/교훈: 원하면 실제 전송·초기 로딩 측정 후 분리 검토. 설정 경고와 사용자 성능 문제를 구분한다.

## H-03 · 영구 저장과 서식 일반화 제한
- 근거: App.jsx 상태 관리 및 snuh_receipt.py의 특정 영수증 배치 경고.
- 증상: 새로고침 후 환자·기록·일정 영구 유지가 보장되지 않음. 다른 서식의 정확도는 검증되지 않음.
- 상태: 현재 범위 기록, 미수정. 과거 장애 재현 결과는 아님.
- 조치: DB 저장·범용 OCR 서비스라는 소개를 제거하고 사용자 검수를 명시.
- 교훈: 외부 OCR 텍스트 인식 성공과 업무 필드의 정확한 구조화는 별도다.

API의 타임아웃·불량 JSON·형식/크기 검증 처리는 코드에 존재하지만 실제 외부 실패를 재현한 것은 아니다. 디버그 OCR 원본은 민감 자료일 수 있어 읽거나 업로드하지 않았다.


## H-04 · 2026-10-25 화면 재로딩 후 기록 소실
- 상태: 영구 저장 코드 구현, 실제 DB 연결·재로딩 검증 대기.
- 사용자 증상: 업로드·OCR·일정·수정 확인 후 화면이 깜빡이며 목록 전체 소실.
- 근거/원인: 기존 App.jsx의 useState에만 기록 보관. 재로딩을 유발한 원인은 미확인.
- 조치: DB 트랜잭션 저장 및 초기 조회. DB 오류 시 임시 저장으로 성공 표시하지 않음.
- 한계: 이미 소실된 과거 메모리는 복구하지 못함. 새 DB 저장 후 재조회·재시작 확인 필요.

## H-05 · 2026-10-25 로컬 개발 환경
- Node/npm: 초기 Codex 내부 Node만 사용되어 일반 VS Code에서 npm 미인식. 공식 Node 24.22.1/npm 11.19.1 설치, .vscode 로컬 터미널 PATH 적용. 전역 PATH 변경은 레지스트리 권한으로 거부됨.
- PowerShell: 사용자가 npm.ps1 실행 정책 차단 보고. npm.cmd 사용으로 실행하도록 안내, 보안 정책 변경하지 않음.
- 백엔드 미실행: OCR 화면 연결 오류 보고 후 사용자 서버 실행 로그 확인. GET / 404는 루트 경로 미정의이며 /docs 사용 안내.
- 에이전트 환경: 서버 시작 로그 이후 루프백 HTTP 접속은 시간 초과. 사용자 실제 실행·OCR 성공 확인과 구분.
- 의존성 설치: 파일 복사 권한 오류가 있었으나 uv 캐시를 workspace로 분리하고 재시도, psycopg/httpx import 확인.

## H-06 · 2026-10-25 DB 구현 중 입력 모델 오류
- 상태: 수정·import 확인 완료.
- 증상: time 필드와 datetime.time 이름 중복으로 TypeError 발생.
- 조치: Date/Time 타입 별칭으로 분리. Python 문법 검사뿐 아니라 main 앱 import도 수행.
- 기존 린트: App.jsx의 Date.now 생성값은 DB 서버 생성 시각으로 대체. InsuranceClaims.jsx의 no-control-regex는 별도 기존 항목.


## H-07 · 2026-10-25 PostgreSQL 삭제 보호 오류 분류
- 상태: 해결. 실제 DB 통합 테스트 통과.
- 증상: 연결 문서가 있는 환자 삭제가 차단되었으나 API가 예상 409 대신 422 반환.
- 원인: PostgreSQL ON DELETE RESTRICT의 SQLSTATE 23001(RestrictViolation)을 ForeignKeyViolation과 별도로 처리해야 함.
- 조치: 두 오류를 모두 409로 매핑. FK 삭제 보호·트랜잭션 롤백 포함 실제 DB 통합 테스트 재실행, 3개 전부 통과.
- DB 초기화 첫 시도는 일반 실패 응답, 재시도 연결 및 초기화 성공. 초기 실패 상세 원인은 미확인.


## H-08 · 2026-10-26 다른 PC 실행 안내 불일치
- 상태: 문서 수정. 학교 PC 자체 실행은 미검증.
- 증상/근거: README는 Python 환경 생성·DB 초기화를 생략하고 API 주소가 고정이라고 설명했으나, 현재 코드는 VITE_API_BASE_URL을 지원한다.
- 조치: 학교 PC 안내 추가, 현재 버전·명령·DB 백업/복원·비밀값 제외를 README와 연결.
- 검증: 로컬 기존 환경과 깨끗한 의존성 설치 점검 결과는 validation.md에 기록. 원격 반영 결과는 Git 이력으로 확인.
- 교훈: 코드 복사와 환경 설정·DB 기록 이동을 구분한다.

## H-09 · 2026-10-26 검증용 uv 캐시 권한 오류
- 상태: 작업 폴더의 캐시 경로를 명시해 재시도.
- 증상: 새 가상환경 점검에서 sandbox 임시 uv 캐시의 파일 저장이 거부되어 재시도 반복.
- 원인 근거: uv가 기본 사용자 캐시 경로에 인터프리터 정보를 쓰려 했으며 os error 5 발생.
- 조치: UV_CACHE_DIR를 쓰기 가능한 작업 폴더로 지정. 프로젝트 실행 코드·사용자 .env는 변경하지 않음.
- 최종 검증 결과는 validation.md 참조. 학교 PC 일반 설치 오류와 구분.
- 후속 결과: 캐시와 copy 방식 지정 후 새 Python 환경 설치·실제 DB 테스트 3개 통과. 별도 npm ci는 node_modules 생성 EPERM으로 두 차례 실패해 미검증 상태로 기록. 기존 프로젝트 프런트 검사·빌드는 통과. 사용자 프로젝트 의존성·서비스 기능을 변경하거나 관리자 실행으로 우회하지 않음.

## H-10 · 2026-10-26 Git 작성자 정보 미설정
- 상태: 확인된 GitHub 계정과 비공개 noreply 이메일을 해당 커밋 명령에만 지정해 해결.
- 증상: 첫 커밋에서 Author identity unknown. 커밋·푸시 전에 중단됨.
- 조치: 인증된 rbgus4560 계정의 작성자 정보로 재시도. 전역 Git 설정을 변경하거나 개인 이메일을 새로 공개하지 않음.
- 검증: 커밋 및 원격 main SHA 일치 여부로 확인.

## H-11 · 2026-10-26 Git HTTPS 인증 도우미 실행 실패
- 상태: GitHub 연결 도구로 업로드 경로 전환. 원격 반영과 로컬 트리 일치 여부를 확인한 뒤 완료로 판단.
- 증상: git push에서 MSYS sh의 NtCreateDirectoryObject 접근 거부, credential-manager get 실패, Username 입력 불가.
- 조치: 인증 정보를 화면·명령에 노출하거나 전역 설정을 바꾸지 않고 인증된 GitHub 연결의 트리·커밋·브랜치 갱신 기능 사용. 원격은 기존 main에서 정상 진행하며 강제 푸시하지 않음.
- 로컬 미게시 커밋은 codex 접두사의 백업 브랜치에 보존하고, 원격과 트리가 일치할 때만 로컬 main을 게시된 커밋으로 동기화.
